# The `lib/` folder

`src/lib/` holds **all non-component application code** — anything that is not a React route or a UI component. UI lives in `src/app/` and `src/components/`; everything else (data access, state, i18n, types, helpers, config) lives here. The project uses a `src/` directory, so this folder is `src/lib/` and the `@/` alias resolves to `src/` (import it as `@/lib/…`). Paths below are shown relative to `src/lib/`.

This skill documents each subfolder, its naming conventions, and the exact patterns to reproduce. The `project-structure` skill is the map; read it first.

## `clients/` — the Axios layer

A single generic class is the **only** code that issues HTTP requests. Everything else (data hooks) instantiates it. Default-exported from `lib/clients/axios/client.ts`.

```ts
class AxiosClient<GenericReq, GenericRes = object> {
  constructor({ endpoint, contentType = "multipart/form-data", locale = "en", baseURL = BACKEND_BASE })
  // request interceptor sets:  Content-Type + Accept-Language: <locale>
  getItem()       // → ItemResponse<GenericRes>
  getList()       // → ListResponse<GenericRes>
  getPaginated()  // → ListPaginated<GenericRes>
  post(body?)  put(body?)  delete()
}
export default AxiosClient;
```

Key points to reproduce:
- Two generics: `GenericReq` (request body) and `GenericRes` (the item type the backend returns).
- `baseURL` defaults to `BACKEND_BASE` (from `lib/constants`); `locale` is sent as the `Accept-Language` header so the backend returns localized content.
- Response types come from the `backend` ambient module (`ItemResponse`, `ListResponse`, `ListPaginated`) — see `types/backend.d.ts`.
- Auth-token handling exists as commented-out scaffolding in the interceptor (the site is public/read-only). **For igotme this is where the Supabase access token would be attached** — see `api-folder`.

## `constants/` — config & static data

- `app.ts` exports the runtime config read from env: `FRONTEND_BASE = process.env.NEXT_PUBLIC_FRONTEND_DOMAIN`, `BACKEND_BASE = process.env.NEXT_PUBLIC_BACKEND_DOMAIN`; the responsive `SCREENS` map (`mobile 412, tablet 820, laptop 1240, desktop 1500` — mirrors the Tailwind `screens`); the Next `appMetadata: Metadata` object (title/description/openGraph/twitter/verification); and `socialMediaLinks`.
- `index.ts` is a **barrel** that re-exports only the public constants (`BACKEND_BASE`, `FRONTEND_BASE`, `SCREENS`, `appMetadata`). Import from `@/lib/constants`, not the inner file.
- Feature files (`nav-bar.ts`, `landing.ts`, `points-bundles.ts`, …) hold large structured, **non-translatable** data (links, ordering, point-bundle sizes/prices, image keys). Translatable strings go in `locales/`, not here.

## `enums/` — routes & endpoints

`enums/app.ts` defines two enums, re-exported via `enums/index.ts`:
- **`Routs`** — frontend route paths (note the spelling). Detail routes use a literal `ID` placeholder: `PROBLEM_DETAILS = "/problems/ID"`.
- **`Endpoints`** — API paths. For igotme these are internal Route Handlers (`/api/…`) or Supabase queries. Detail endpoints use the `ID` placeholder: `GET_PROBLEM_DETAILS = "/api/problems/ID"`.

The `ID` placeholder is replaced at call time with `.replace("ID", id)` (data hooks) and `navigate({ href, replacements })` (useLocale). Keep this convention so routes/endpoints stay declarative.

## `helpers/` — pure functions

Plain TS, no React, no side effects. `dateManipulators.ts` provides `formatTime` (→ `"06 June 2026"`), `dateToLocalTime` (→ `"6:30 PM"`), and `dateToTimeAgo` (relative). Add new cross-feature pure utilities here; one file per concern, camelCase filename, named exports.

## `hooks/` — data hooks + helper hooks

Two clearly separated subfolders; `hooks/index.tsx` barrels the most-used ones (currently just `useLocale`).

### `hooks/data/` — server state (one file per resource)

Every data hook follows the same shape: get `locale` → new `AxiosClient` → wrap in a TanStack Query hook.

```ts
export const useGetProblems = () => {
  const { locale } = useLocale();
  const client = new AxiosClient<unknown, Problem>({ endpoint: Endpoints.GET_PROBLEMS, locale });
  return useInfiniteQuery<ListPaginated<Problem>, Error>({
    queryKey: ["GetProblems"],
    queryFn: ({ pageParam }) => client.getPaginated({ params: { page: pageParam, page_size: 10 } }),
    getNextPageParam: (last, all) => (last?.pagination?.next ? all.length + 1 : undefined),
    staleTime: 24 * 60 * 60 * 1000, retry: false, initialPageParam: 1,
  });
};

export const useGetProblemDetails = (id: string) => {
  const { locale } = useLocale();
  const client = new AxiosClient<unknown, ProblemDetails>({
    endpoint: Endpoints.GET_PROBLEM_DETAILS.replace("ID", id), locale,
  });
  return useQuery({ queryKey: ["GetProblemDetails", id], queryFn: () => client.getItem() });
};
```

Conventions:
- Naming: `useGet<Resource>` (list) and `useGet<Resource>Details` (item). Lists that paginate use `useInfiniteQuery` + `getPaginated`; small/fixed lists use `useQuery` + `getList`; single items use `useQuery` + `getItem`. Mutations (create problem, spend points, checkout) use `useMutation` — see `api-folder`.
- `queryKey` is a stable string + any params (`["GetProblemDetails", id]`).
- Resource/response types come from the per-resource ambient modules (`problems`, `character`, `backend`).

### `hooks/helpers/` — UI/util hooks (all `"use client"`)

- **`useLocale.tsx` (core).** Derives the locale from the pathname (`/{locale}/…`), returns `{ locale, toggleLocale, t, navigate, currentRout }`. `t` is the active dictionary (`en`/`ar` from `locales/`). `navigate({ href, replacements })` swaps `ID`→value then pushes `"/" + join(locale, href)`. `toggleLocale` rewrites segment 1 of the path. This hook ties i18n, routing, and translations together — almost every client component uses it.
- `useInfiniteScrollFetch.tsx` — pairs a `useInfiniteQuery` result with `useInView` to auto-`fetchNextPage` when a sentinel scrolls into view; returns `{ listRef, isFetchingNextPage, transformedData }` (pages flat-mapped).
- `useInView.tsx` (IntersectionObserver), `useWindowSize.tsx` (returns viewport width + `currentScreen` from `SCREENS`), `useHorizontalScrollDrag(.ts/2.tsx)` (drag-to-scroll).

## `locales/` — file-based i18n (no library)

Translations are plain TS objects, not JSON, and there is no i18n runtime dependency.

- `i18n.config.ts`: `export const i18n = { defaultLocale: "en", locales: ["en", "ar"], localDetection: true } as const;` — the `as const` makes `Locale` a literal union. **This same config is consumed by `middleware.ts`** (see `dynamic-routes`).
- `data/<feature>.ts` exports two named objects with the same shape: `<feature>EN` and `<feature>AR` (e.g. `landingEN` / `landingAR`).
- `en.ts` / `ar.ts` aggregate the feature objects into one dictionary keyed by feature (`{ forms, global, nav, footer, landing, auth, character, problems, points }`) and **default-export** it.
- `useLocale().t` returns whichever dictionary matches the active locale; components read `t.landing.title`, etc.

To add a translated string: add it to both `…EN` and `…AR` in the relevant `data/` file (the `TranslateObject` type keeps them structurally aligned).

## `providers/` — the client provider stack

`providers.tsx` exports `<Providers>` (a Client Component) used once in `app/[locale]/layout.tsx` to wrap all children. Order (outer → inner):

```tsx
<ReduxProvider>       {/* react-redux <Provider> + redux-persist <PersistGate> (LoadingSpinner fallback) */}
  <TanStackProvider>  {/* <QueryClientProvider>: refetchOnWindowFocus:false, staleTime 24h, retry:false */}
    <Toaster richColors closeButton />   {/* sonner */}
    {children}
```

> **No UI provider:** shadcn/ui needs **no** runtime provider, so the base stack is just `ReduxProvider` → `TanStackProvider` → `Toaster`. **Theme toggling:** to support light/dark switching, add a `next-themes` `<ThemeProvider attribute="class" defaultTheme="light">` as the outermost wrapper here. The app is **light by default** (warm dark is the secondary theme) — see `conventions-patterns` → *Dark / light mode* for the full steps.

## `store/` — Redux Toolkit + redux-persist

- `index.ts`: `configureStore({ reducer: reducers, middleware: … ignoring the persist actions [FLUSH, REHYDRATE, PAUSE, PERSIST, PURGE, REGISTER] })`, then `persistStore(store)`. Exports `{ store, persistor }`.
- `reducers.ts`: SSR-safe storage — `createNoopStorage()` when `window` is undefined, else `createWebStorage("local")`. Each slice gets its own `persistReducer` with a `key` and a `whitelist` (empty by default — nothing persisted until added). `combineReducers({ app, auth, points, character })`.
- Slices (`createSlice`): typed `InitialXStateProps`, an `initialState`, reducers that take `{ payload }: StorePayload<T>` (the shared payload type from `lib/types`), and an exported selector `select<Slice> = (state) => state.<slice>`.

```ts
export const appSlice = createSlice({ name: "app", initialState, reducers: { setIsMobileNavDrawerOpen: (state, { payload }) => { state.isMobileNavDrawerOpen = payload; } } });
export const { setIsMobileNavDrawerOpen } = appSlice.actions;
export const selectApp = (state: { app: InitialAppStateProps }) => state.app;
```

## `styles/`

`globals.css` is the single global stylesheet, imported once in the root layout. With shadcn it also hosts the Tailwind directives and the CSS-variable design tokens — the **single source of truth for the look**: `--primary` (`#E3C9A1` warm beige), `--secondary` (`#D8A7A5` dusty rose), `--tertiary` (`#A6BE9D` sage green), `--radius`, the font variables, plus `--background`, `--foreground`, `--border`, … as HSL channels. **`:root` = the default light (cozy cream) theme; `.dark` = the optional warm-dark overrides.** Re-branding or re-tuning either theme is an edit here only. See `stack-dependencies` → *Design tokens (colors)* and `conventions-patterns` → *Dark / light mode*.

## `types/` — shared types & ambient modules

Two flavors:
- **Real modules (`.ts`)** — `app.ts` exports `Locale = (typeof i18n)["locales"][number]`, `StorePayload<T> = { payload: T }`, `ScreenType`, and `TranslateObject = typeof en | typeof ar`. Barrelled by `index.ts`; import via `@/lib/types`.
- **Ambient declaration modules (`.d.ts`)** — each resource declares a bare module: `declare module "problems" { type Problem = …; type ProblemDetails = …; }`, `declare module "backend" { type ItemResponse<T> … }`. These are imported by **bare specifier** (`import { Problem } from "problems"`), not a path — that's why the data hooks and AxiosClient write `from "backend"` / `from "problems"`.

To add a resource: create `types/<resource>.d.ts` with `declare module "<resource>"`, a matching `enums` endpoint, and a `hooks/data/<resource>.ts` hook.

## Recreation order

1. `types/` — `backend.d.ts`, `app.ts` (+ `index.ts`), then per-resource `.d.ts` as needed.
2. `constants/app.ts` (+ `index.ts`) and `enums/app.ts` (+ `index.ts`).
3. `locales/i18n.config.ts`, `data/*`, `en.ts`/`ar.ts`.
4. `clients/axios/client.ts`.
5. `hooks/helpers/useLocale.tsx`, then `hooks/data/*` per resource.
6. `store/` (slices → reducers → index) and `providers/` (Tanstack, Redux, then composed `providers.tsx`).
7. `styles/globals.css`, `helpers/*`, and `utils.ts` (via `shadcn init`).

> **igotme adaptation:** keep this exact layout. Add `lib/clients/supabase/` (browser + server clients) alongside `axios/`, point `hooks/data/*` at Supabase queries or internal `/api` routes, attach the Supabase token in the Axios interceptor where the commented auth block is, and add `store` slices for points/auth/character state. Details in `api-folder` and `stack-dependencies`.
